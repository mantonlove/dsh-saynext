# 建议质量评测

日常使用的数据可在 DSH 会话顶部的“建议统计”查看。以下为开发者复核相同口径的离线流程。

客户端用本地文字规则同时初判意图与严重性。数据源是曾展示的建议、同会话紧接的本人消息及该轮已有的用户要求。两项分别显示已判定的分母，待判断排除，部分命中计入意图分母。某一项经人工纠正后立即按新值计算，撤销后恢复自动值。自动与人工条数按建议计，同一条的两项可来自不同来源。离线回放保留独立人工评阅，用于检验自动判断。

评测工具在源码仓库的 `scripts` 下，通过命令手动运行。线上安装不会运行这些脚本。

| 指标 | 分子 | 分母 | 证据 |
| --- | --- | --- | --- |
| 显示覆盖率 | 实际看到灰字的回合 | 插件开启、正常结束、有可用空输入框和展示机会的回合 | 受控窗口逐帧读取可见输入框及灰字 |
| 意图命中率 | 关注对象、行动和执行人都吻合 | 有建议且能判定的回合 | 预测封存后揭晓真实下一句，逐条人工判读；部分命中另报 |
| 严重误判率 | 至少出现一项严重错误 | 已评阅严重性的建议 | 标出擅自授权、换目标、虚构决定、转移责任；每条最多计一次 |
| 可直接使用率 | 本人下一条已发送的纯文本与展示文本逐字一致 | 已展示且能确认后续发送的回合 | 受控界面实际展示与 DSH 后续本人消息。填入后改写另计 |

同会话同回合使用同一个样本编号。重复渲染算一次。受控窗口从一轮结束前开始观察，观察至下一次发送或明确结束。测试驱动在每个可见帧调用 `observeFrame(document, rounds)`，把实际调用 `inputActions.setDraft` 的结果记在测试驱动内。用 `followup(log, turn)` 读取其后确认发送的消息。观察期未覆盖、未完成评阅或无法确定时留空。关闭观察且确认未发送用 `false`。这些操作只在开发者发起的测试中进行。

历史回放按会话划分留出集，先固定版本、模型、采样参数和样本。两个版本仅接收截至对应回合结束的相同上下文。收集经过筛选、重试后最终送往输入框的候选，留空也保留记录。回放报告用“候选产出率”标注，真实显示覆盖率与原样发送率留空。由自动化投递的后续消息须注明来源，不可据此推断个人表达偏好。

### 运行

预测文件为 JSON 对象。以下是一条受控测试用的格式示例。context 填相同输入前缀的摘要值，id 标识会话和回合。

```json
{"version":"candidate","mode":"observed","cases":[{"id":"A/7","context":"prefix-hash","opportunity":true,"status":"shown","text":"四月的数据从哪里来？"}]}
```

用 `npm run evaluate -- freeze 预测.json` 封存文件，再打开真实下一句评分。正式比较为两个版本分别封存。将下列评阅记录放在单独的 JSON 数组里。

```json
[{"id":"A/7","intent":"hit","errors":[],"filled":true,"send":"四月的数据从哪里来？"}]
```

运行 `npm run evaluate -- score 预测.json 评阅.json`，或追加第二组预测和评阅文件同时比较。脚本核对封存摘要、重复回合、版本间样本和上下文一致性。覆盖率绝对差不超过事先约定的 5 个百分点才标为可比。每项输出分子、分母和百分比，分母为零时百分比为 null。

- `status` 支持受控界面的 `shown`、历史回放的 `candidate`，以及 `skip`、`failure`、`late`、`ineligible`、`unknown`。仅凭观察器没有看到灰字时保留 unknown。核实生成留空、失败或晚到后才填写原因。有机会但展示未知时给覆盖率上下界。
- `intent` 用 `hit`、`partial`、`miss` 或 null。用户换了话题可能导致预测未命中；仅凭换题不能推断建议严重有错。
- `errors` 用数组，标签为 `authorization`、`goal-change`、`invented-decision`、`wrong-actor`。空数组表示评过且无严重错误，null 表示未评。
- `send` 填已确认的下一句。带附件用 `{"attachments":true}`，缺失用 null。回放数据不得填写 `send` 或 `filled`。单纯点过 Enter 或没点 Enter 均不产生意图标签。

### 与 Codex 输入框建议同题对照

在普通 Codex 会话中，先记录回合和屏幕上实际出现的完整建议，再记录用户自己发送的下一句。截图或可核实的界面记录留在本机。未观测到建议且无法确认原因时标为 `unknown`。将同一回合截至助手答复的可见对话按相同顺序交给 SayNext，生成时隐去后续用户消息。两份记录共用样本编号和可见对话前缀摘要值。

原生记录用 `observed`，SayNext 回放用 `replay`。分别执行 `freeze` 后揭晓下一句，按相同标准评阅两组输出。运行 `npm run evaluate -- paired Codex预测.json Codex评阅.json SayNext预测.json SayNext评阅.json` 查看共同出建议的回合数、状态组合，以及双方均可判定的意图和严重性。单方留空、观测未知和技术失败分别计数。实际展示覆盖率和原样发送率只在对应产品有真实展示、发送观测时报告。
